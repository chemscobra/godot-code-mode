# Build and verification

- Godot API floor: 4.7; the checked-in API dump comes from Godot 4.7.2.
- Linux editor build: `cmake -B build -DGODOTCPP_TARGET=editor -DCMAKE_BUILD_TYPE=Release && cmake --build build -j 6`.
- Windows x86-64 editor cross-build: `cmake -B build-windows -DCMAKE_TOOLCHAIN_FILE=toolchains/mingw-w64.cmake -DGODOTCPP_TARGET=editor -DCMAKE_BUILD_TYPE=Release && cmake --build build-windows -j 6`. Use a fresh build directory when switching toolchains. The toolchain statically links the MinGW runtime.
- Generic MCP integration tests (pytest): `pytest tools/test_bridge` (requires `godot` on PATH, or `--godot /path/to/godot`). Tests are plain functions ordered by numbered modules (`test_10_*`…`test_90_denied`); select with `-k`, e.g. `pytest tools/test_bridge -k permissions`. `tools/test_generic_bridge.py` remains the entry point and forwards extra pytest args: `python3 tools/test_generic_bridge.py -- -k variant_matrix -x`. Shared state lives in `tools/bridge_harness.py` (`BridgeSession` + ordered `STAGES`): each test calls `session.ensure("<stage>")`, which lazily runs prerequisite stages on the same session-scoped editor boot. Requires `pytest` installed for the Python running the entry point (e.g. a venv).
- Regenerate the checked-in declarations with `python3 tools/test_generic_bridge.py --write-declarations`; typecheck with `npm exec --yes --package=typescript@5.8.3 -- tsc --noEmit --strict --target ES2020 addons/godot_cm/api-surface.d.ts`.
- Isolated performance comparison: `python3 tools/test_generic_bridge.py --benchmark --baseline-021` then `python3 tools/test_generic_bridge.py --benchmark`. The baseline is extracted from the local v0.2.1 tag without checkout; see docs/benchmarks.md for its legacy batch-handle caveat.
- Fast Variant inventory check: `python3 -B tools/test_generic_bridge.py --inventory-only`; checks all 39 fixture categories against the API dump and godot-cpp enum without launching the editor.
- Catalog invalidation/lifetime test: `GODOT_CM_PROFILE=1 python3 -B tools/test_generic_bridge.py --catalog-lifecycle`. On Linux this compiles test-only reloadable extensions using `c++` and the configured SDK archive in `build/bin`, inside the temporary project; it verifies a real signature-changing native reload, pinned snapshots, 24 script invalidation cycles and bounded catalog/cache lifetimes. Do not combine it with benchmark capture or shipped declaration generation.
- Optional real-extension/physics test: `python3 tools/test_generic_bridge.py --terrain-addon /path/to/project/addons/terrain_3d`.
- Tests create isolated temporary projects and copy the optional third-party addon. Do not import or run tests against the user's example project: Godot may rewrite project settings and import metadata.
- The isolated fixture seeds `.godot/extension_list.cfg` before initial import so native classes are available at editor startup.
- Scene construction, resource persistence, playback and runtime-result retrieval in the optional physics test use MCP. Its temporary observer script only samples a generic rigid body; it does not integrate Terrain3D.
- Keep third-party implementations/adapters out of `src/` and `addons/godot_cm/`. Test-only plugin usage belongs in `tools/` or isolated fixtures.
- Before finishing: rebuild both native binaries after source/version changes, run relevant integration tests, and run `git diff --check`. A successful Windows cross-build does not establish Windows runtime compatibility.
- Activation tests exercise the shipped EditorPlugin, immediate disable/re-enable, pending/running status, occupied ports, and measure checkbox latency separately from service readiness. Startup discovers native APIs from ClassDB without parsing the static API dump; inherited signatures are shared within each immutable catalog.
- Normal activation skips diagnostic spike checks and TypeScript generation. Opt in with `GODOT_CM_RUN_CHECKS=1` or `GODOT_CM_GENERATE_DTS=1` when developing; generated declarations are written to `user://godot_cm-api-surface.d.ts`.

# Manual testing
- `examples/demo-project/` is a deterministic, committed sandbox for manual MCP testing: `addons/godot_cm` is a symlink to the dev addon, plus vendored third-party plugins (Terrain3D v1.0.2 Linux-only binaries, PhantomCamera v0.12) for exercising non-builtin classes. Its `.godot/` and editor state are gitignored; do not use it in the automated suite — that fixture stays fully temporary.
